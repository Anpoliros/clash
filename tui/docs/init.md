# Init Docs

本文档说明如何在一个没有文档或文档较弱的项目中启动 `docs/` 体系。它不绑定具体技术栈，适用于前端、后端、脚本工具、内容站点和混合型项目。

目标不是一次写完所有文档，而是先建立稳定入口，让维护者和 coding agent 可以快速判断：

- 项目有哪些关键目录和模块。
- 源码路径应该读哪份文档。
- 修改代码后应该如何同步更新文档。
- 后续新增文档应该遵循什么模板。

## 最小可用文档集

没有文档的项目可以先创建以下三份文件：

```txt
docs/README.md
docs/MAP.md
docs/SPEC.md
```

三份文件的职责如下：

- `README.md`：文档入口，说明文档目录、使用方式和集成方式。
- `MAP.md`：文档地图，维护源码路径、配置路径、内容路径与文档路径的映射。
- `SPEC.md`：文档规范，定义模板、更新规则和质量要求。

## 第一批项目文档

最小文档集之后，优先补最能降低理解成本的文档。不同项目可以按实际目录命名，不需要照搬下面的路径。

```txt
docs/architecture/overview.md
docs/modules/<core-module>.md
docs/workflows/development.md
```

建议优先覆盖：

- 项目入口：路由、命令行入口、服务启动入口或主程序入口。
- 核心数据流：数据从哪里来、如何转换、最终输出到哪里。
- 关键模块：最常改、最容易误改、影响范围最大的模块。
- 工程流程：开发、测试、构建、部署、内容同步、数据迁移。
- 外部边界：环境变量、第三方服务、存储目录、生成产物。

## 初始化步骤

1. 创建 `docs/README.md`、`docs/MAP.md`、`docs/SPEC.md`。
2. 扫描项目顶层目录、配置文件、脚本和入口文件。
3. 在 `MAP.md` 中先写“源码路径 -> 建议文档路径”的映射。
4. 按影响范围挑 3 到 8 篇最高价值文档先写。
5. 在项目的 agent 指令或贡献指南中加入轻量文档规则。
6. 后续每次修改核心逻辑时，同时检查 `MAP.md` 和相关文档。

## MAP.md 建议格式

Markdown 表格最通用，适合人工和 agent 阅读：

```md
| Source Path | Documentation | Update When |
| --- | --- | --- |
| `src/server/` | `docs/modules/server.md` | 修改服务启动、请求处理或中间件时 |
| `src/domain/order/` | `docs/modules/order.md` | 修改订单模型、状态流转或接口契约时 |
| `scripts/deploy.sh` | `docs/workflows/deploy.md` | 修改部署命令、环境变量或产物路径时 |
```

如果项目需要被程序读取，也可以额外维护 `docs/map.json` 或 `docs/map.yaml`。但建议保留 `MAP.md` 作为人工入口，避免文档索引变成只有机器能读的配置。

## 文档命名建议

- 使用小写路径和短文件名，例如 `docs/workflows/deploy.md`。
- 面向目录的文档命名为 `overview.md`，面向能力的文档用能力名。
- 不按每个源码文件一比一建文档，除非该文件是稳定公共接口或关键入口。
- 决策文档使用递增编号，例如 `docs/decisions/0001-docs-structure.md`。

## 通用集成方式

建议在项目的 agent 指令、贡献指南或 README 中只保留轻量规则，把详细规范放在 `docs/`：

```md
## 文档维护规范

- 修改核心模块、公共接口、数据模型、构建流程或部署流程时，必须检查 `docs/`。
- 开始修改前，优先查看 `docs/MAP.md`，确认源码路径对应的文档。
- 文档写作、模板和更新规则见 `docs/SPEC.md`。
```

对于没有 agent 指令文件的项目，可以把上面规则放在：

- `AGENTS.md`
- `CONTRIBUTING.md`
- `README.md`
- 团队内部开发指南

## 迁移已有文档

如果项目已经有零散文档，不建议马上重写。更稳妥的迁移方式是：

- 先创建 `MAP.md`，把已有文档挂到对应源码路径上。
- 再创建 `SPEC.md`，统一后续新增文档的格式。
- 只在修改相关模块时整理旧文档，不做无业务背景的大规模搬迁。
- 对过期文档加“状态说明”，不要让 agent 把旧信息当作事实。

## 完成标准

一个项目的文档系统达到“可启动”状态，至少应满足：

- 新人或 agent 能从 `docs/README.md` 知道怎么读文档。
- 修改任意核心目录前，能从 `docs/MAP.md` 找到相关文档或建议文档路径。
- 新增文档时，能从 `docs/SPEC.md` 找到模板和更新规则。
- 至少有一篇核心模块文档和一篇工程流程文档。
